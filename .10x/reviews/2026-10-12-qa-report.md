## Bugs found and fixed during verification
1. Wrapped headings were split into two paragraphs, because Docstrum estimates spacing per page. Fixed by `MergeContinuations`.
2. Paragraphs were not split at blank lines or around images. Fixed by `SplitParagraphs`, which uses a gap relative to font size.
3. Junk metadata titles ("novel.html") were used as book titles. They now fall back to the file name.
4. **nginx served `/api/**.png` as static files (404).** The regex location took priority over the `/api/` prefix. Fixed with `location ^~ /api/`.
5. nginx `add_header` inheritance dropped the security headers in locations that set their own headers. Fixed with a shared include.
6. Sessions were lost when the container restarted. Fixed by persisting the data-protection keys on the data volume.

## Known gaps / not tested
- **Password-protected PDFs:** the code maps them to a friendly error, but there is no encrypted fixture because PdfPig cannot write encryption. Test manually with a real encrypted file.
- **Scanned (image-only) PDFs** are shown as images. There is no OCR (out of scope for v1).
- **Right-to-left and vertical (CJK) text** is not covered by fixtures.
- **Very large PDFs** (> 500 pages) were not load-tested. There is a hard cap at 5,000 pages.
- **The upload-size 413 path** was only tested through its code branch, not with an actual 100 MB body.

## Follow-up (2026-10-12): unstyled production build
- **Bug:** In the Docker/nginx build the global stylesheet never applied (default form controls, underlined links, full-size sidebar thumbnails). Angular's production `inlineCritical` loads the stylesheet with `media="print" onload="this.media='all'"`; the inline `onload` handler is blocked by our CSP `script-src 'self'`.
- **Fix:** `optimization.styles.inlineCritical: false` in `angular.json` → plain `<link rel="stylesheet">`. Verified on :8080.
- **Lesson:** always verify the production image, not only `ng serve`. Check: `curl -s localhost:8080 | grep onload` must be empty.
